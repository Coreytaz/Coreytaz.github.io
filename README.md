# Stepan Bykov — portfolio

Двуязычное портфолио frontend-разработчика: React, Next.js App Router, TypeScript, Tailwind CSS и shadcn/ui на Base UI. Готовый HTML публикуется в GitHub Pages. Сервер, база данных и CMS для работы сайта не нужны.

## Запуск

Используйте Node.js **26.12.0** (`.nvmrc` / `.node-version`) и npm **12.2.0**:

```sh
npm install --global npm@12.2.0
npm ci
npm run dev
```

Откройте http://localhost:3000. Для просмотра именно статической production-сборки:

```sh
npm run build
npm run preview
```

Не запускайте dev и preview одновременно на одном порту. `out/` — готовый сайт; его не нужно коммитить.

## Редактирование содержимого

Основной файл — **`content/portfolio.json`**. Его можно редактировать локально или прямо через интерфейс GitHub. Изменение, сохранённое в `main`, запускает проверки и публикацию. Ошибка в JSON остановит сборку, предыдущая опубликованная версия останется доступна.

| Раздел               | Что меняет                                                |
| -------------------- | --------------------------------------------------------- |
| `site`               | Базовый домен, заголовок и описание сайта для поисковиков |
| `profile`            | Имя, специализацию, представление, описание и контакты    |
| `copy.ru`, `copy.en` | Все основные подписи интерфейса                           |
| `skills`             | Группы навыков и ссылки на подтверждающие проекты         |
| `experience`         | Реальный опыт работы; пустой массив скрывает раздел       |
| `projects`           | Карточки, кейсы, порядок, публикацию и ссылки             |

Все локализованные значения содержат **`ru` и `en`**. `null` в `email`, `telegram`, `resume` скрывает соответствующую ссылку. Имя и GitHub уже заполнены; остальные личные данные нужно добавить самостоятельно. Резюме задаётся внешним HTTPS-адресом. Версия для печати доступна без отдельного PDF.

### Добавить или опубликовать проект

1. Скопируйте объект существующего проекта в массив `projects`.
2. Задайте уникальный `slug` из строчных латинских букв, цифр и дефисов. Он становится частью URL; после публикации лучше его не менять.
3. Заполните `title`, `category`, `summary`, `overview`, `features`, `decisions`, `technologies`, `imageAlt` и ссылки. Используйте только реальные сведения. Пустые массивы `features` и `decisions` скрывают соответствующие секции кейса.
4. Для изображения положите оригинал PNG/JPEG/WebP/AVIF в `assets/`, задайте `imageSource: "assets/filename.png"` и `image: "/images/projects/{slug}.webp"`. Рекомендуется ширина от 1440 px и горизонтальный формат. Сборка автоматически создаст WebP. Имя файла — латинские буквы, цифры, пробелы, дефисы или подчёркивания.
5. Задайте `demoUrl`: внешний HTTPS-адрес вне GitHub Pages. Не используйте адрес другого проекта. `repositories` — список объектов `label` / `url`; GitHub разрешён для исходников.
6. Укажите `status: "published"`, `featured: true` для избранного и `order` для сортировки по возрастанию. Первая избранная работа получает крупную карточку. Опубликованные проекты с `featured: false` показываются в дополнительном списке.
7. Выполните `npm run content:check`, затем `npm run build` и проверьте страницы на обоих языках.

`status: "draft"` сохраняет запись только в исходном JSON. Она не попадёт в HTML, клиентские данные, sitemap, JSON-LD, социальные карточки или набор опубликованных превью. Исходный GitHub-репозиторий публичный: черновик в нём не является приватным документом.

Перенесены 12 проектов. Опубликованы AnimBook, React Chat и SpaceX Ships. Остальные девять ждут корректных внешних демо. У «Автосервиса» удалена ошибочная ссылка на SpaceX Ships; у Golden Property Solution удалена ошибочная ссылка на Legalide. Старые проекты не обновлялись до нового стека — их технологии описаны отдельно от технологий портфолио.

### Валидация и изображения

`content/portfolio.schema.json` даёт подсказки в редакторе. Источник схемы и дополнительных проверок — `src/lib/content-schema.ts`. После изменения структуры выполните `npm run content:schema` и сохраните обновлённую схему в Git.

`npm run assets:build` оптимизирует опубликованные превью и создаёт OG-карточки для обоих языков. Сгенерированные изображения в `public/` хранятся в Git, чтобы dev работал сразу после установки. При снятии проекта с публикации его сгенерированные превью и OG-карточки удаляются из `public/`; исходник остаётся в `assets/`. Каталоги `public/images/projects/` и `public/og/` генерируются автоматически: не храните в них единственную копию изображения. Для изменения контента и путей к оригиналам достаточно одного `portfolio.json`.

## Проверки

```sh
npm run check
npm run build
npx playwright install chromium
npm run test:e2e
npm run lighthouse
npm audit
```

Для Linux CI: `npx playwright install --with-deps chromium`. Если Chromium CDN недоступен, можно использовать установленный Chrome: PowerShell — `$env:PLAYWRIGHT_CHANNEL='chrome'`, bash — `PLAYWRIGHT_CHANNEL=chrome npm run test:e2e`.

`npm run check` проверяет JSON, код, типы и негативные сценарии схемы. ESLint проверяет JS-конфигурацию, Oxlint — TypeScript, React, hooks, Next.js и доступность. Это позволяет использовать TypeScript 7 без несовместимого peer dependency текущего typescript-eslint. Обходы `--force` и `--legacy-peer-deps` не используются.

Playwright проверяет desktop/mobile, обе локали, прямое открытие кейсов и перезагрузку, сохранение темы, клавиатуру, мобильное меню, печать, отсутствие JS, SEO, 404 и исключение черновиков из всего артефакта. Axe проверяет WCAG AA в светлой и тёмной теме.

Lighthouse использует установленный Chrome, временно запускает статический сервер на порту 4173 и сохраняет отчёты в `reports/`. Проверяются RU, EN и кейс; пороги — Performance 90, Accessibility 95, SEO 95. Результат зависит от браузера и окружения. Отчёты и скриншоты не коммитятся.

## GitHub Pages

1. В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
2. Сохраните изменения в `main` или запустите workflow вручную.
3. Workflow устанавливает зафиксированные Node/npm, выполняет `npm ci`, проверку схемы, линтеры, типы, unit-тесты, аудит, сборку и браузерные тесты. Только успешный результат публикует `out/`.
4. Pull request запускает проверки и сохраняет браузерный отчёт, но не публикует сайт.

Адрес: **https://coreytaz.github.io/**. Для этого пользовательского репозитория `basePath` не требуется. При смене домена обновите `site.baseUrl` и настройки Pages; для собственного домена добавьте `public/CNAME`.

Страницы RU находятся в `/`, EN — в `/en/`; кейсы — `/projects/{slug}/` и `/en/projects/{slug}/`. Отдельные корневые layout задают правильный HTML `lang`. Sitemap и hreflang содержат только опубликованные страницы. Данные читаются на этапе сборки, не скачиваются браузером из JSON. Настройки серверных redirects, ISR, API и оптимизации изображений на запросе не используются.

GitHub Pages отдаёт `404.html` для неизвестных адресов. После сборки скрипт копирует HTML специальной страницы `/page-not-found/` в корневой `404.html`. Она закрыта от индексации и отсутствует в sitemap.

## Обновление зависимостей и UI

Все прямые зависимости при создании проверены по npm `latest` и закреплены lock-файлом. Для обновления повторно проверьте `npm outdated`, поставьте актуальные стабильные версии, выполните все проверки и сохраните `package-lock.json`. npm-скрипт esbuild разрешён адресно через `allowScripts` для npm 12.

Компоненты созданы через **shadcn CLI 4.22.1**, preset **Base Nova**, и находятся в `src/components/ui/`. Общие CSS-утилиты экспортированы официальной командой `shadcn eject`: CLI не нужен при сборке, а его лишние транзитивные зависимости не входят в проект. При обновлении UI добавляйте компоненты через `npx shadcn@latest add ...`; если CLI вернул CSS-зависимость, повторите `npx shadcn@latest eject --yes` и проверьте изменения. После eject общие утилиты обновляются явно вместе с компонентами.

Все шрифты и изображения локальные. Внешние трекеры, cookies аналитики, форма отправки сообщений и сторонние runtime API отсутствуют.
