# Stepan Bykov — portfolio

Двуязычное портфолио frontend-разработчика: React, Next.js App Router, TypeScript, Tailwind CSS и shadcn/ui на Base UI. Готовый HTML публикуется в GitHub Pages. Сервер, база данных и CMS для работы сайта не нужны.

## Запуск

Используйте Node.js **26.12.0** (`.nvmrc` / `.node-version`) и npm **12.2.0**:

```sh
npm install --global npm@12.2.0
npm ci
npm run dev
```

Откройте http://localhost:3000. Для просмотра именно статической production-сборки:

```sh
npm run build
npm run preview
```

Не запускайте dev и preview одновременно на одном порту. `out/` — готовый сайт; его не нужно коммитить.

## Стили

Оформление страниц, адаптивность, hover/focus и печатные варианты задаются utility-классами Tailwind CSS 4 непосредственно в компонентах `src/components/`. Компоненты React Bits также используют Tailwind и не импортируют отдельные CSS-файлы. Нестандартные размеры и эффекты используют arbitrary values и variants; `String.raw` сохраняет экранирование подчёркиваний в селекторах React Bits.

`src/app/globals.css` содержит подключение Tailwind, токены светлой и тёмной темы, базовые настройки документа, скроллбар, keyframes, View Transitions и глобальное отключение движения. Здесь не нужно добавлять оформление отдельных карточек или секций. Короткие имена классов вроде `project-card` сохранены как DOM-маркеры для взаимодействий, селекторов и браузерных тестов; сами стили задают соседние utility-классы.

## Редактирование содержимого

Основной файл — **`content/portfolio.json`**. Его можно редактировать локально или прямо через интерфейс GitHub. Изменение, сохранённое в `main`, запускает проверки и публикацию. Ошибка в JSON остановит сборку, предыдущая опубликованная версия останется доступна.

| Раздел               | Что меняет                                                |
| -------------------- | --------------------------------------------------------- |
| `site`               | Базовый домен, заголовок и описание сайта для поисковиков |
| `profile`            | Имя, специализацию, представление, описание и контакты    |
| `copy.ru`, `copy.en` | Все основные подписи интерфейса                           |
| `skills`             | Группы навыков и ссылки на подтверждающие проекты         |
| `experience`         | Реальный опыт работы; пустой массив скрывает раздел       |
| `projects`           | Карточки, кейсы, порядок, публикацию и ссылки             |

Все локализованные значения содержат **`ru` и `en`**. `null` в `email`, `telegram`, `resume` скрывает соответствующую ссылку. Имя и GitHub уже заполнены; остальные личные данные нужно добавить самостоятельно. Резюме задаётся внешним HTTPS-адресом. Версия для печати доступна без отдельного PDF.

### Добавить или опубликовать проект

1. Скопируйте объект существующего проекта в массив `projects`.
2. Задайте уникальный `slug` из строчных латинских букв, цифр и дефисов. Он становится частью URL; после публикации лучше его не менять.
3. Заполните `title`, `category`, `summary`, `overview`, `features`, `decisions`, `technologies`, `imageAlt` и ссылки. Используйте только реальные сведения. Пустые массивы `features` и `decisions` скрывают соответствующие секции кейса.
4. Для изображения положите оригинал PNG/JPEG/WebP/AVIF в `assets/`, задайте `imageSource: "assets/filename.png"` и `image: "/images/projects/{slug}.webp"`. Рекомендуется ширина от 1440 px и горизонтальный формат. Сборка автоматически создаст WebP. Имя файла — латинские буквы, цифры, пробелы, дефисы или подчёркивания.
5. Задайте `demoUrl`: внешний HTTPS-адрес вне GitHub Pages. Не используйте адрес другого проекта. `repositories` — список объектов `label` / `url`; GitHub разрешён для исходников.
6. Укажите `status: "published"`, `featured: true` для избранного и `order` для сортировки по возрастанию. Первая избранная работа получает крупную карточку. Опубликованные проекты с `featured: false` показываются в дополнительном списке.
7. Выполните `npm run content:check`, затем `npm run build` и проверьте страницы на обоих языках.

`status: "draft"` сохраняет запись только в исходном JSON. Она не попадёт в HTML, клиентские данные, sitemap, JSON-LD, социальные карточки или набор опубликованных превью. Исходный GitHub-репозиторий публичный: черновик в нём не является приватным документом.

Перенесены 12 проектов. Опубликованы AnimBook, React Chat и SpaceX Ships. Остальные девять ждут корректных внешних демо. У «Автосервиса» удалена ошибочная ссылка на SpaceX Ships; у Golden Property Solution удалена ошибочная ссылка на Legalide. Старые проекты не обновлялись до нового стека — их технологии описаны отдельно от технологий портфолио.

### Валидация и изображения

`content/portfolio.schema.json` даёт подсказки в редакторе. Источник схемы и дополнительных проверок — `src/lib/content-schema.ts`. После изменения структуры выполните `npm run content:schema` и сохраните обновлённую схему в Git.

`npm run assets:build` оптимизирует опубликованные превью и создаёт OG-карточки для обоих языков. Сгенерированные изображения в `public/` хранятся в Git, чтобы dev работал сразу после установки. При снятии проекта с публикации его сгенерированные превью и OG-карточки удаляются из `public/`; исходник остаётся в `assets/`. Каталоги `public/images/projects/` и `public/og/` генерируются автоматически: не храните в них единственную копию изображения. Для изменения контента и путей к оригиналам достаточно одного `portfolio.json`.

## Проверки

```sh
npm run check
npm run build
npx playwright install chromium
npm run test:e2e
npm run lighthouse
npm audit
```

Для Linux CI: `npx playwright install --with-deps chromium`. Если Chromium CDN недоступен, можно использовать установленный Chrome: PowerShell — `$env:PLAYWRIGHT_CHANNEL='chrome'`, bash — `PLAYWRIGHT_CHANNEL=chrome npm run test:e2e`.

`npm run check` проверяет JSON, код, типы и негативные сценарии схемы. ESLint проверяет JS-конфигурацию, Oxlint — TypeScript, React, hooks, Next.js и доступность. Это позволяет использовать TypeScript 7 без несовместимого peer dependency текущего typescript-eslint. Обходы `--force` и `--legacy-peer-deps` не используются.

Playwright проверяет desktop/mobile, обе локали, прямое открытие кейсов и перезагрузку, сохранение темы, клавиатуру, мобильное меню, печать, отсутствие JS, SEO, 404 и исключение черновиков из всего артефакта. Axe проверяет WCAG AA в светлой и тёмной теме.

Lighthouse использует установленный Chrome, временно запускает статический сервер на порту 4173 и сохраняет отчёты в `reports/`. Проверяются RU, EN и кейс; пороги — Performance 90, Accessibility 95, SEO 95. Результат зависит от браузера и окружения. Отчёты и скриншоты не коммитятся.

## GitHub Pages

1. В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
2. Сохраните изменения в `main` или запустите workflow вручную.
3. Workflow устанавливает зафиксированные Node/npm, выполняет `npm ci`, проверку схемы, линтеры, типы, unit-тесты, аудит, сборку и браузерные тесты. Только успешный результат публикует `out/`.
4. Pull request запускает проверки и сохраняет браузерный отчёт, но не публикует сайт.

Адрес: **https://coreytaz.github.io/**. Для этого пользовательского репозитория `basePath` не требуется. При смене домена обновите `site.baseUrl` и настройки Pages; для собственного домена добавьте `public/CNAME`.

Страницы RU находятся в `/`, EN — в `/en/`; кейсы — `/projects/{slug}/` и `/en/projects/{slug}/`. Отдельные корневые layout задают правильный HTML `lang`. Sitemap и hreflang содержат только опубликованные страницы. Данные читаются на этапе сборки, не скачиваются браузером из JSON. Настройки серверных redirects, ISR, API и оптимизации изображений на запросе не используются.

GitHub Pages отдаёт `404.html` для неизвестных адресов. После сборки скрипт копирует HTML специальной страницы `/page-not-found/` в корневой `404.html`. Она закрыта от индексации и отсутствует в sitemap.

## Анимации и View Transitions

Анимации включены по умолчанию. Кнопка рядом с темой в Header отключает их глобально; выбор хранится в localStorage и применяется до отрисовки страницы. Системная настройка уменьшения движения не переопределяет этот выбор.

- Первый экран появляется последовательно; декоративные элементы двигаются мягко и независимо.
- Секции проектов, навыков, описания и контактов появляются при прокрутке через IntersectionObserver и Web Animations API. Без JS содержание остаётся видимым.
- Переходы между страницами используют стабильный React 19.3 ViewTransition. Превью и заголовок проекта имеют общие имена на карточке и странице кейса.
- Смена темы раскрывает новый снимок страницы кругом от кнопки, по мотивам [theme-toggle.rdsx.dev](https://theme-toggle.rdsx.dev/). Эффект очищается после завершения, повторного переключения или выключения анимаций.
- При смене языка используется непрозрачный снимок основного содержимого View Transition; текст заменяется целиком без наложения переводов.
- Выключение анимаций останавливает CSS-переходы, плавную прокрутку, JS-анимации появления и активный View Transition. Браузеры без API переключают тему и открывают страницы обычным способом.

Стили — в globals.css, границы переходов — MotionView, появление секций — PageMotion, круг темы — theme-transition.ts. Новые эффекты должны учитывать общий MotionProvider. Нормализация файлов предзагрузки в finalize-export.ts добавляет плоские алиасы для вложенных сегментов Windows-сборки, чтобы статическому хостингу не требовались rewrites.

### React Bits

Переключатель языка работает через Next.js App Router без перезагрузки документа: RU и EN используют общий корневой layout. Сдвиг содержимого на 2 px без размытия длится 180 ms и отключается общей настройкой анимаций. Если native View Transition недоступен, используется тот же небольшой сдвиг через Web Animations без скрытия содержимого и перезагрузки документа. Тема, настройки курсора и состояние глобальных провайдеров сохраняются. `DocumentLocale` обновляет язык HTML при клиентской навигации, а `finalize-export.ts` выставляет корректный `lang` во всех экспортированных HTML для поисковиков и режима без JavaScript.

Карточки проектов используют SpotlightCard: превью неподвижны при наведении, а описание и действия находятся в общей рамке. Возможности избранного проекта и подписи технологий берутся из JSON. Кейсы сохраняют общие View Transition для реального изображения и заголовка. На touch/reduced motion и при отключении анимаций превью остаются статичными.

Первый экран использует TiltedCard с несколькими слоями (`@react-bits/TiltedCard-TS-CSS`, выбран через MCP). Декоративное окно интерфейса наклоняется до 7° с лёгким бликом. На touch/reduced motion эффект не запускается; глобальное отключение анимаций отменяет RAF, сбрасывает transform и убирает обработчики. Начальная разметка не зависит от темы браузера, а цвета берутся из CSS-токенов.

Контактный блок использует SpotlightCard и Magnet (`@react-bits/Magnet-TS-CSS`, выбран через MCP): круглая кнопка открывает почту, а отдельные карточки показывают контакты из JSON. Магнитное смещение ограничено 12 px; общий переключатель анимаций сбрасывает смещение и освобождает обработчики. На телефонах основными действиями остаются контактные карточки. Декор исключён из печати.

Навигация в шапке использует локальный `PillNav` из React Bits, выбранный через shadcn MCP (`@react-bits/PillNav-TS-CSS`). Цвета связаны с токенами темы; заливка и перекат текста учитывают общий переключатель анимаций. На главной сохраняются нативные якорные ссылки, на внутренних страницах — Next Link. Мобильное меню остаётся доступным через Sheet. Исходники и адаптированные стили находятся в `src/components/react-bits/PillNav.*`, лицензия — в `third-party/react-bits-LICENSE.md`.

Кастомный курсор (`CustomCursor`) использует акцентный цвет темы и SVG-стрелку. Шлейф — адаптированный [Glow Cursor из React Bits](https://reactbits.dev/animations/glow-cursor), локальный WebGL-компонент `src/components/react-bits/GlowCursor.tsx`. Он загружается отдельно и работает только с мышью при включённых анимациях. На сенсорных устройствах и при forced colors эффект не монтируется. Для курсора общий переключатель сайта управляет анимацией независимо от системного reduced motion. При недоступном WebGL или потере контекста включается резервный Canvas-шлейф. При вводе текста и навигации с клавиатуры остаётся системный указатель. Общий переключатель анимаций отключает и кастомный указатель, и шлейф: возвращается системный курсор, обработчики снимаются, эффект размонтируется и освобождает GPU-ресурсы. HEX-цвета читаются напрямую, без canvas readback. Лицензия сохранена в `third-party/react-bits-LICENSE.md`.

Реестр `@react-bits` подключён в `components.json`. Для работы с ним через MCP используется [shadcn MCP](https://ui.shadcn.com/docs/mcp), настроенный отдельно в пользовательском `~/.codex/config.toml`. MCP не входит в зависимости и production-сборку сайта; после его подключения перезапустите Codex. Доступность проверена настоящим MCP-запросом поиска Waves в `@react-bits`.

В `src/components/react-bits/` сохранены TypeScript/CSS-исходники [Star Border](https://reactbits.dev/animations/star-border) и [Spotlight Card](https://reactbits.dev/components/spotlight-card), полученные из официального реестра React Bits 20 октября 2026 года. Star Border подсвечивает контур кнопки проектов на первом экране, Spotlight Card — превью проектов под курсором. Дополнительные npm-зависимости не нужны.

Фон первого экрана — [Waves](https://reactbits.dev/backgrounds/waves), также из официального реестра. `HeroBackground` загружает WebGL2-компонент отдельным чанком: тонкие линии с шагом 18 px, DPR 0.75, до 30 кадров/с. Цвета и прозрачность подобраны под светлую и тёмную темы. При глобальном выключении компонент размонтируется и освобождает GPU-ресурсы; вне экрана и в фоновой вкладке отрисовка приостанавливается. При `prefers-reduced-motion` рисуется статичный кадр. Без JS или WebGL остаётся CSS-градиент; при печати фон скрыт.

Палитра Waves разбирается из HEX без `getImageData`: защита от считывания canvas не должна превращать цветной фон в серую заливку. Регрессионные тесты подменяют чтение пикселей белым цветом и блокируют его исключением, проверяя насыщенность палитры, передаваемой в WebGL.

Очистка Waves удаляет программы и буферы, но не вызывает `loseContext()` на живом canvas: React StrictMode и Fast Refresh повторяют эффекты на том же элементе. До первого кадра и при потере WebGL-контекста canvas скрыт, остаётся CSS-градиент; при восстановлении контекста программа создаётся заново. Для проверки в режиме разработки запустите `npm run dev`, затем в другом PowerShell выполните `$env:PLAYWRIGHT_BASE_URL='http://localhost:3000'; $env:PLAYWRIGHT_CHANNEL='chrome'` и `node node_modules/@playwright/test/cli.js test tests/e2e/hero-background.spec.ts`. Playwright использует указанный сервер без запуска второго процесса. Адрес должен совпадать с адресом dev-сервера: Next.js может блокировать dev-ресурсы при подмене localhost на 127.0.0.1. Production-тесты по умолчанию работают на отдельном порту 4178.

### Страницы ошибок

404 и 500 используют [Fuzzy Text](https://reactbits.dev/text-animations/fuzzy-text) из реестра React Bits: крупный код ошибки с мягким искажением и усилением при наведении. Эффект загружается отдельным чанком только при показе ошибки. Код ошибки и пояснение есть в HTML; без JS, при выключенных анимациях или печати отображается обычный текст. Canvas работает с частотой до 30 кадров/с, учитывает `prefers-reduced-motion` и удаляется при глобальном выключении. Авторство и лицензия находятся в `third-party/react-bits-LICENSE.md`.

Предпросмотр: `/page-not-found/`, `/500/` и соответствующие страницы с префиксом `/en/`. Экспорт содержит `/404.html`, `/500.html`, `/en/404.html`, `/en/500.html`; страницы исключены из sitemap и помечены `noindex`. Тексты редактируются в `content/portfolio.json`. В обработчиках `error.tsx` для обоих языков тот же экран 500 позволяет повторить загрузку через актуальный `retry()` Next.js; ссылка на главную выполняет полную загрузку, чтобы выйти из сломанного состояния. Исходное сообщение исключения пользователю не выводится.

GitHub Pages автоматически использует только корневой `404.html`. Файл `500.html` подготовлен для хостинга с настройкой серверных страниц ошибок: GitHub Pages не позволяет назначить собственную страницу для ошибок инфраструктуры. Прямое открытие `/500/` — предпросмотр с HTTP 200, а ошибка React показывает экран 500 в текущем документе без изменения его HTTP-статуса. Локальный статический сервер отдаёт 404 с правильным статусом и языком и использует `500.html` с HTTP 500 при непредвиденной ошибке чтения файлов.

Адаптации: цвета и размеры портфолио, остановка обработчиков и requestAnimationFrame через MotionProvider, отключение подсветки на устройствах без hover, обновление настроек через эффекты React. Canvas кнопки останавливается за пределами экрана. Исходные компоненты учитывают `prefers-reduced-motion`; при глобальном выключении эффекты полностью скрываются. Текст, ссылки и статический контур кнопки доступны без JavaScript. Уведомление об авторстве и лицензия MIT + Commons Clause сохранены в `third-party/react-bits-LICENSE.md`.

Браузерные тесты проверяют реальные снимки и keyframes, отмену эффекта, сохранение настроек, RU/EN, fallback без API и отсутствие запросов 404 при переходе в кейс. Контраст проверяется после завершения конечных анимаций, без их отключения.

## Обновление зависимостей и UI

Все прямые зависимости при создании проверены по npm `latest` и закреплены lock-файлом. Для обновления повторно проверьте `npm outdated`, поставьте актуальные стабильные версии, выполните все проверки и сохраните `package-lock.json`. npm-скрипт esbuild разрешён адресно через `allowScripts` для npm 12.

Компоненты созданы через **shadcn CLI 4.22.1**, preset **Base Nova**, и находятся в `src/components/ui/`. Общие CSS-утилиты экспортированы официальной командой `shadcn eject`: CLI не нужен при сборке, а его лишние транзитивные зависимости не входят в проект. При обновлении UI добавляйте компоненты через `npx shadcn@latest add ...`; если CLI вернул CSS-зависимость, повторите `npx shadcn@latest eject --yes` и проверьте изменения. После eject общие утилиты обновляются явно вместе с компонентами.

Все шрифты и изображения локальные. Внешние трекеры, cookies аналитики, форма отправки сообщений и сторонние runtime API отсутствуют.
